### 1. `remaining_issues` 是一个明确 bug

你现在 `_preflight_and_repair()` 返回：

```python
{
    "repairs_applied": 0,
    "implicit_resolutions": [],
    "blocking_issues": None,
    "warnings": None,
}
```

已经把原来的 `remaining_issues` 拆成了 `blocking_issues` 和 `warnings`。

但 `generate_dsl()` 还在：

```python
if stats["repairs_applied"] or stats["remaining_issues"]:
```



如果：

```text
repairs_applied == 0
```

左边为 False，就会访问不存在的：

```text
stats["remaining_issues"]
```

然后 `KeyError`。

直接改成：

```python
if (
    stats["repairs_applied"]
    or stats["blocking_issues"]
    or stats["warnings"]
    or stats["implicit_resolutions"]
):
    meta["preflight"] = stats
```

不过我更推荐：

```python
meta["preflight"] = stats
```

**只要跑过 Preflight 就始终返回 stats。**

这样诊断数据最完整，不需要猜：

```text
meta.preflight is None
```

到底是“没问题”还是“根本没执行”。

## 2. 这是一个隐藏得比较深的 Prompt bug

```python
    system_prompt: str | None = None
```

里面写的是：

```python
 "content": system_prompt or SYSTEM_PROMPT}
```

这意味着：


**并不是“没有 system prompt”。**

```python
_call_llm(
```


```text

          ↓

    Repair Candidate Choose
```

角色是串的。

这可能也是你之前一些 LLM 输出莫名波动的来源之一。

```python
PLANNER_SYSTEM_PROMPT = """..."""
```


不要再用 `None` 表示“特殊模式”。

# 5. 前端存在一个实际 XSS 点

你虽然写了：

```javascript
escapeHtml(r.error)
```

这个很好。

但是：

```javascript
innerHTML = `
...
<strong>${r.action}</strong>
<span>${r.target || ""}</span>
<span>${r.value || ""}</span>
...
`
```

这里的：

```text
r.action
r.target
r.value
```

没有 escape。

而 DSL 编辑框允许用户手动修改。

比如：

```json
{
  "value": "<img src=x onerror=alert(1)>"
}
```

执行报告把它原样返回，再塞进 `innerHTML`，就可能执行。

最简单：

```javascript
escapeHtml(String(r.action || ""))
escapeHtml(
    typeof r.target === "object"
        ? JSON.stringify(r.target)
        : String(r.target || "")
)
escapeHtml(String(r.value || ""))
```

更好的方式是不要拼 `innerHTML`，用：

```javascript
element.textContent = ...
```

# 8. Locator 的 `count()` 会牺牲 Playwright 自动等待能力

目前：

```python
count = locator.count()

if count == 1:
    return locator
```



对 SPA：

```text
当前 0 个
↓
100ms 后按钮出现
```

你会立即判：

```text
LocatorNotFound
```

但 `click()` 本来会自动等待。

所以这句注释：

> click/input 要求元素已经存在

其实会让你的执行器比原生 Playwright **更容易 flaky**。

Demo 可以改成：

```python
try:
    locator.first.wait_for(
        state="attached",
        timeout=timeout_ms,
    )
except Exception:
    continue

count = locator.count()

if count == 1:
    return strategy, locator

if count > 1:
    raise LocatorAmbiguousError(...)
```

这里 `.first` 只是：

> 等待至少有一个候选出现

**不是最终选择第一个元素。**

最终仍然通过 count 保证唯一性。

# 14. 你的凭据正则会误伤 URL

这里：

```python
re.compile(
    r'(\S+)\s*/\s*([^\s，,。;；]+)'
)
```



可以把：

```text
https://example.com
```

中的 `/` 解释成：

```text

```

建议至少要求 `/` 两边有空格：

```python
re.compile(
```

更稳：

```python
re.compile(
    r'(?:login\s+with|账号|用户名)'
    r'\s*[:：]?\s*'
    r'([^\s,/]+)'
    r'\s+/\s+'
    r'([^\s,，。;；]+)',
    re.IGNORECASE,
)
```

并补一个回归测试：

```text
https://example.com
```

绝对不能产生：


# 15. DSL 的 Pydantic 校验还不算真正“安全边界”

目前 DSLStep 主要只是：

```python

target: ...

value: ...
timeout_ms: int
```



所以这些都能通过：

```json
{
  "action": "click",
  "target": null
}
```

```json
{
  "action": "goto",
  "value": null
}
```

```json
{
  "action": "assert_url"
}
```

```json
{
  "action": "fill",
  "target": {"role": null}
}
```

Pydantic 类型合法，但**业务语义非法**。

建议加 `model_validator`：

```python
if action == "goto":

    require(value)

elif action == "assert_url":
    require(value)
```

```python
timeout_ms: int = Field(

    ge=100,
    le=60000,
)
```

# 16. 建议所有 Pydantic Model `extra="forbid"`

现在 LLM 输出：

```json
{
  "target": {
    "role": "button",
    "name": "Login",
    "xpath": "xxxx"
  }

```

这会产生一种危险情况：

# 18. Executor 建议默认 fail-fast

# 19. 你的诊断脚本还有一个指标 bug

这个挺值得修。

`semantic_signature()` 会把**所有 step**都加入：

```python
sig.append({
    "action": ...,
    ...
})
```

然后：

```python
action_hash()
```

直接 hash 整个 `semantic_signature`。

因此：

```text
最后 assert 不一样
```

也会导致：

```text
action_hash 不一样
```

但你又单独做了：

```text
verify_hash
```

所以两个指标现在不是独立的。

你之前：

```text
Run3
action_hash 不同
verify_hash 不同
```

很可能**核心 interaction actions 其实完全一样**，只是最终 verification 不一样。

应该：

```python
def action_signature(case):
    return [
        normalize(s)
        for s in case["steps"]
        if s["action"] not in {
            "assert_visible",
            "assert_text",
            "assert_url",
        }
    ]
```

这样才真正得到：

```text
core_action_stability
```

我甚至怀疑你目前：

```text
3/4 core action stability
```

修完后可能直接变：

```text
4/4
```
